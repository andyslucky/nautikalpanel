Nautikal Panel stores all data directly in Kubernetes — game server configurations are serialized as StatefulSet annotations and settings are stored in Kubernetes ConfigMaps. There is no external database to configure or manage.

## How Data is Stored

### Game Server Configurations

All game server data is embedded in Kubernetes StatefulSet annotations using the `nautikal.io/game-server-spec` annotation. This means your server configurations:
- Survive pod restarts and rescheduling
- Are backed up with standard Kubernetes cluster backups
- Can be inspected with `kubectl describe statefulset <server-id> -n nautikal`

### Template Repositories

Template repository settings are stored in a Kubernetes ConfigMap (`nautikal-settings`) in the configured namespace:

```bash
kubectl get configmap nautikal-settings -n nautikal -o yaml
```

### Benefits of K8s-Native Storage

- **No database to manage** — No extra container, volume, or backup process
- **Kubernetes-native backups** — Standard `etcd` snapshots back up all data
- **Multi-instance consistency** — All instances read from the same ConfigMap
- **Zero configuration** — No connection strings, credentials, or database setup

## Backup and Restore

Since all data lives in Kubernetes, use standard Kubernetes backup tools:

```bash
# Export all StatefulSets (includes game server specs)
kubectl get statefulsets -n nautikal -o yaml > nautikal-statefulsets.yaml

# Export settings ConfigMap
kubectl get configmap nautikal-settings -n nautikal -o yaml > nautikal-settings.yaml

# Restore
kubectl apply -f nautikal-statefulsets.yaml
kubectl apply -f nautikal-settings.yaml
```
