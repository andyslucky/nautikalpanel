This guide covers deploying Nautikal Panel to production Kubernetes clusters using the official OCI Helm chart published to the GitHub Container Registry.

## Prerequisites

Before installing Nautikal Panel, ensure you have:

- **Kubernetes cluster** (v1.19+) with kubectl configured
- **Helm 3.8+** installed on your local machine (OCI support required)
- **Storage class** configured in Kubernetes (or specify a default)

:::tip
For development or testing, see the [Development](/getting-started/development) guide for building and running from source.
:::

## Installation

The recommended way to install Nautikal Panel is using the OCI Helm chart from GHCR.

### Install from GHCR

```bash
helm install nautikalpanel oci://ghcr.io/andyslucky/nautikalpanel \
  --namespace nautikalpanel --create-namespace
```

:::caution
Helm does not support `helm repo add` for OCI registries. Always use the `oci://` URL directly with `helm install` or `helm upgrade`.
:::

### Install with Custom Values

Create a `custom-values.yaml` file:

```yaml
controllers:
  main:
    replicas: 2

persistence:
  data:
    storageClass: fast-ssd
    size: 20Gi

ingress:
  main:
    enabled: true
    className: nginx
    hosts:
      - host: nautikalpanel.example.com
        paths:
          - path: /
            pathType: Prefix
            service:
              identifier: main
              port: http
    tls:
      - hosts:
          - nautikalpanel.example.com
        secretName: nautikalpanel-tls

config:
  kubernetes:
    defaultStorageClass: fast-ssd
```

Install with custom values:

```bash
helm install nautikalpanel oci://ghcr.io/andyslucky/nautikalpanel \
  -f custom-values.yaml \
  --namespace nautikalpanel --create-namespace
```

### Using GitHub Token for Template Repositories

If you need to fetch templates from private GitHub repositories, create a Kubernetes secret first:

```bash
kubectl create secret generic my-github-token \
  --from-literal=github-token=YOUR_TOKEN_HERE \
  --namespace nautikalpanel
```

Then reference it in your values:

```yaml
githubToken:
  existingSecret: my-github-token
  existingSecretKey: github-token
```

:::danger
Never set a GitHub token as a plaintext value in `values.yaml`. The chart only supports reading from an existing Kubernetes secret via `secretKeyRef`.
:::

## Accessing Nautikal Panel

### Using Port-Forward

```bash
kubectl port-forward svc/nautikalpanel 8080:80 -n nautikalpanel
```

Then access at http://localhost:8080

### Using LoadBalancer Service

Update `values.yaml`:

```yaml
service:
  main:
    type: LoadBalancer
```

Then get the external IP:

```bash
kubectl get svc nautikalpanel -n nautikalpanel
```

### Using Ingress

Enable ingress in `values.yaml` and configure your ingress controller:

```yaml
ingress:
  main:
    enabled: true
    className: nginx
    hosts:
      - host: nautikalpanel.example.com
        paths:
          - path: /
            pathType: Prefix
            service:
              identifier: main
              port: http
```

## Upgrading

To upgrade an existing installation:

```bash
helm upgrade nautikalpanel oci://ghcr.io/andyslucky/nautikalpanel \
  --namespace nautikalpanel
```

To upgrade with custom values:

```bash
helm upgrade nautikalpanel oci://ghcr.io/andyslucky/nautikalpanel \
  -f custom-values.yaml \
  --namespace nautikalpanel
```

## Uninstalling

To remove Nautikal Panel:

```bash
helm uninstall nautikalpanel --namespace nautikalpanel
```

## Configuration

The Helm chart uses the [bjw-s common library](https://github.com/bjw-s-labs/helm-charts/tree/main/charts/library/common) for standard Kubernetes resources. Key parameters include:

| Parameter | Description | Default |
|-----------|-------------|---------|
| `controllers.main.replicas` | Number of replicas | `1` |
| `controllers.main.containers.main.image.repository` | Image repository | `ghcr.io/andyslucky/nautikalpanel` |
| `controllers.main.containers.main.image.tag` | Image tag | `""` (uses `appVersion`) |
| `service.main.type` | Service type | `ClusterIP` |
| `service.main.ports.http.port` | Service port | `80` |
| `ingress.main.enabled` | Enable ingress | `false` |
| `persistence.data.enabled` | Enable persistence | `true` |
| `persistence.data.storageClass` | Storage class | `""` |
| `persistence.data.size` | Storage size | `10Gi` |
| `config.server.host` | Server host | `0.0.0.0` |
| `config.server.port` | Server port | `9090` |
| `config.kubernetes.namespace` | Kubernetes namespace for game servers | `nautikal` |
| `config.kubernetes.defaultStorageClass` | Default storage class for game servers | `""` |
| `rbac.clusterScoped` | Use `ClusterRole` (true) or `Role` (false) | `false` |

For the complete list of configuration options, see the [Helm chart README](https://github.com/andyslucky/nautikalpanel/blob/main/charts/nautikalpanel/README.md) and the [values.yaml](https://github.com/andyslucky/nautikalpanel/blob/main/charts/nautikalpanel/values.yaml) file.

## Storage Configuration

Ensure your Kubernetes cluster has a default storage class, or specify one:

```bash
# Check available storage classes
kubectl get storageclass

# If no default, mark one as default
kubectl patch storageclass standard -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
```

Or configure in the Helm values:

```yaml
config:
  kubernetes:
    defaultStorageClass: your-storage-class
```

## RBAC

By default, the chart creates a namespace-scoped `Role` and `RoleBinding`. This is sufficient when Nautikal Panel is deployed in the same namespace it manages game servers in.

If the target namespace (`config.kubernetes.namespace`) differs from the release namespace, set:

```yaml
rbac:
  clusterScoped: true
```

This will create a `ClusterRole` and `ClusterRoleBinding` instead, allowing cross-namespace resource management.

### Permissions

The role grants the following permissions:

- `get`, `list`, `watch`, `create`, `update`, `patch`, `delete`, `deletecollection` on `pods`, `services`, `persistentvolumeclaims`, `secrets`, `configmaps`
- `get`, `list`, `watch`, `create`, `update`, `patch`, `delete`, `deletecollection` on `statefulsets`
- `get`, `watch`, `list` on `pods/log`
- `get`, `list`, `watch` on `events`

These permissions are required for Nautikal Panel to manage game server resources.

## Verifying Installation

After deploying Nautikalpanel:

1. Check that the pods are running:
   ```bash
   kubectl get pods -n nautikalpanel
   ```

2. Check the service status:
   ```bash
   kubectl get svc nautikalpanel -n nautikalpanel
   ```

3. Open a browser to the external IP address (or use port-forward as shown above)

4. You should see the Nautikalpanel dashboard
5. Click "Add Server" to verify templates are loaded

## Troubleshooting

### Pod Not Starting

Check pod status and logs:

```bash
kubectl get pods -n nautikalpanel
kubectl logs -f deployment/nautikalpanel -n nautikalpanel
```

### Service Not Accessible

Check service status and events:

```bash
kubectl get svc nautikalpanel -n nautikalpanel
kubectl describe svc nautikalpanel -n nautikalpanel
```

### Permission Errors

Verify the service account has correct RBAC permissions:

```bash
kubectl auth can-i create pods \
  --as=system:serviceaccount:nautikalpanel:nautikalpanel \
  -n nautikal
```

### Storage Issues

Check PersistentVolumeClaim status:

```bash
kubectl get pvc -n nautikalpanel
kubectl describe pvc -n nautikalpanel
```
